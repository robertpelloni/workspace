# ITGmania Project Architecture and Learnings

## 1. Project Overview & Vision
* **ITGmania** is an advanced cross-platform rhythm game forked from StepMania 5.1.
* **Core Directive**: The primary architectural shift involves incrementally porting the C++ backend and core engine functionality to **Rust** to improve memory safety and performance.
* **UI Strategy**: The C++ frontend/UI layers are to be maintained, relying on a robust Foreign Function Interface (FFI) boundary to communicate with the new Rust backend.

## 2. Documentation Standards
The project adheres to a strict documentation governance model to enable continuous, autonomous execution across sessions. The following master files must be maintained in the root directory:
* `VISION.md`: Tracks the ultimate goal and foundational design.
* `MEMORY.md`: Stores architectural observations and codebase traits.
* `DEPLOY.md`: Deployment and environment setup instructions.
* `IDEAS.md`: Aggressive ideas for refactoring, pivoting, or feature expansions.
* `CHANGELOG.md`: Tracks every adjustment and global version bumps.
* `ROADMAP.md`: Long-term structural milestones.
* `TODO.md`: Granular short-term features and bug fixes.
* `HANDOFF.md`: Captures system state for session handoffs between agents.

## 3. Build System & Rust Integration
* **Primary Build System**: CMake (`CMakeLists.txt`).
* **Rust Crate Integration**: 
  * A new crate, `rust_core`, is located in `src/rust_core/`.
  * It compiles as a static library (`crate-type = ["staticlib"]`) generating `librust_core.a`.
  * CMake integrates this via an `add_custom_target` that invokes `cargo build --release` and an `IMPORTED STATIC` library that links to the main `itgmania` executable.
* **Compatibility**: The Rust crate is pinned to the `2021` edition. Unstable features like `#[unsafe(no_mangle)]` (introduced in Rust 2024) should be avoided in favor of standard `#[no_mangle]` to ensure broad CI compatibility across standard toolchains.

## 4. FFI Strategy (C++ to Rust)
* Functions ported to Rust (e.g., `sm_crash` from `src/global.cpp`) use C Application Binary Interface (ABI) definitions.
* **Rust Side**: Exposed using `#[no_mangle] pub extern "C" fn function_name(...)`. 
* **C++ Side**: Declared inside `#ifdef __cplusplus extern "C" { ... }` blocks in corresponding headers (e.g., `src/global.h`).
* **Preserving Execution Flow**: When porting complex functions that rely on platform-specific C++ macros (like fatal crash handlers invoking OS debuggers or generating crash dumps), the Rust implementation serves as an intercept/logging layer. The original C++ macro logic is preserved and executes immediately after the Rust FFI call returns.

## 5. Dependency Management & Submodule Patterns
* **External Dependencies**: The project heavily relies on external C libraries (e.g., `ffmpeg`, `libpng`, `libjpeg-turbo`, `mbedtls`).
* **Git Submodule Quirks**: 
  * To circumvent recursive submodule cloning failures (due to proxy cache staleness), `extern/` dependencies were removed from `.gitmodules` in favor of a build-time script: `fetch-extern-deps.sh`.
  * **CI Trap**: The previous removal of `.gitmodules` entries left orphaned `160000` tree objects (submodule pointers) in the Git index. This causes GitHub Actions (`actions/checkout@v6`) to crash with exit code `128` when `submodules: recursive` is true.
  * **Fix**: Ensure `git rm --cached` is executed against all `extern/*` submodule directories to completely wipe them from the index, resolving the checkout failure.
* **Environment Setup**: Requires libraries such as `libpulse-dev`, `libasound2-dev`, `libglew-dev`, `libudev-dev`, `nasm`, `yasm`, and X11/GTK3 development files.
* **FFmpeg Compilation**: The bundled FFmpeg dependency encounters inline assembly operand mismatches on modern compilers. This is bypassed by adding `--disable-asm` and `--disable-x86asm` to the `FFMPEG_CONFIGURE` list in `CMake/SetupFfmpeg.cmake`.
