## Unified StepMania: Architectural Overview & Design Patterns

### 1. Core Architecture: The Singleton Manager Pattern
The project follows a strict **Singleton Manager** architecture. All high-level subsystems are encapsulated in global managers initialized and destroyed in `src/StepMania.cpp`.
*   **Managers:** `ECONOMYMAN`, `GYMMAN`, `TOURNAMENTMAN`, `HEARTRATEMAN`, `ASSETSYNCMAN`, `UNIFIED_NET`, `CHATMAN`, `SWARMMAN`, `SPECTATORMAN`, `REPLAYMAN`, `MISSIONMAN`.
*   **Lifecycle:** Initialized during engine startup; modern ownership is managed via `std::unique_ptr` where appropriate, though legacy parts still use raw pointers with `SAFE_DELETE`.
*   **Update Loop:** Most managers are hooked into `GameLoop::UpdateAllButDraw` to ensure frame-by-frame state updates (e.g., heart rate sampling, network packet processing).

### 2. Economy & Blockchain Integration (Bobcoin)
The economy system is built to be "Play-to-Earn" (Proof of Dance).
*   **`BobcoinBridge`**: Implements a JSON-RPC client using `EzSockets` to communicate with a Bobcoin node.

Unified StepMania is built on a robust **Singleton Manager** architecture. All high-level subsystems are encapsulated in global managers that are initialized and destroyed in `src/StepMania.cpp`. *   **Engine Integration:** Managers hook into the main `GameLoop` for frame-by-frame updates, critical for real-time features like heart rate monitoring and network packet handling.
