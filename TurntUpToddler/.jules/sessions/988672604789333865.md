### 1. Architectural Overview
The **Hymn Remaker** project is a high-performance, automated content-generation engine that transforms classical MIDI/MusicXML hymn files into modern, stylized music videos (e.g., Deep House, Synthwave). 

*   **Hybrid Engine**: The core rendering logic is written in native C++ (`src/engine/HymnPlayer.cpp`) using the FluidSynth library. This engine is bridged to Python via `pybind11` as the `hymn_player_ext` module, combining C++'s performance for audio synthesis with Python's flexibility for AI orchestration.
*   **Pipeline Stages**:
    1.  **Ingestion**: Supports `.mid`, `.mxl`, and raw images/PDFs (processed via `oemer` Optical Music Recognition).
    2.  **Synthesis**: Fast, sample-accurate offline rendering of MIDI to raw WAV.
    3.  **Remaking**: Style-conditioned audio transformation using Replicate (MusicGen) or Suno AI.
    4.  **Vocals**: Generative singing/speech via ElevenLabs TTS, including multi-voice spatial harmonies (+4 and +7 semitones) using the `pyrubberband` algorithm.
    5.  **Processing**: AI stem separation via `demucs` to isolate drums and bass for precise vocal ducking in the final mix.
    6.  **Assembly**: Video composition with audio-reactive visualizers and karaoke-style subtitles burned in via FFmpeg.
*   **Broadcasting**: A built-in `RadioStreamer` enables 24/7 RTMP streaming to platforms like YouTube Live.

### 2. Key Design Patterns & Decisions
*   **Continuous Autonomous Execution**: The project is governed by a directive of total autonomy. Features like **Daemon Mode** (directory watching) and **Kids Mode** (automated nursery rhyme downloads and COPPA compliance) allow the system to operate indefinitely without human oversight.
*   **Multi-Stage Docker Optimization**: To manage the massive footprint of ML dependencies (PyTorch, Oemer, Demucs), the project utilizes a 3-stage Docker build:
    *   `builder`: Compiles the C++ engine.
    *   `ml-deps`: Pre-installs heavy ML libraries.
    *   `runtime`: A lean final stage that copies the pre-built engine and ML `site-packages` before installing lightweight application dependencies (Streamlit, API clients).
*   **Idempotency & Cost Governance**: The pipeline implements strict caching (DALL-E MD5 hashes) and skip flags (`--skip-render`, `--skip-remake`) to ensure failed or interrupted jobs can resume without incurring redundant API costs.
*   **Thread Safety in Streamlit**: Background tasks utilize `concurrent.futures`. A critical `add_script_run_ctx` hook is maintained in `app.py` to ensure Streamlit's context is preserved across worker threads.

### 3. Documentation & Governance Protocols
*   **Version Truth**: A single source of truth for the project version resides in the root `VERSION` file, which is synchronized across `docs/VERSION.md` and `hymn_remaker/VERSION.md`.
*   **Comprehensive Documentation Suite**: The project maintains a strict set of Markdown files in `docs/` (`VISION`, `ROADMAP`, `TODO`, `CHANGELOG`, `MEMORY`, `HANDOFF`) to ensure continuity and architectural clarity across development sessions.
*   **Defensive Conflict Resolution**: Merges from fragmented feature branches are handled using the `ours` strategy where appropriate to resolve unrelated histories while preserving the latest functional state (e.g., preserving Kids Mode features during consolidation).

### 4. Technical Maintenance & Insights
*   **Subtitle Robustness**: FFmpeg subtitle burning is identified as a fragile process. The pipeline includes an automatic retry loop that sanitizes lyrics (ASCII-only) and falls back to a textless video render if errors persist.
*   **High-Fidelity Harmonies**: Pitch-shifting for TTS harmonies was shifted from crude framerate stretching to `pyrubberband` to ensure vocal duration remains perfectly synced with the instrumental beat regardless of pitch shift.
*   **Testing Coverage**: The project maintains 25 unit tests covering the C++ extension, TTS logic, metadata generation, and video assembly.

### 5. Future Roadmap (v1.27.0+)
The project is currently transitioning from its Phase 6 "Cloud Native Polish" into Phase 7 "Web Modernization," which focuses on decomposing the Streamlit monolith into a **FastAPI backend** and a **Next.js frontend**, alongside **Kubernetes orchestration** for horizontally scaling audio/video rendering jobs.
