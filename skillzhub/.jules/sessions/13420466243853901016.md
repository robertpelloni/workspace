# SkillzHub - Project Memory & Architecture Summary

## Overview
SkillzHub is a fully scaffolded MVP for a C2B marketplace that connects creators equipped with GoPro/FPV cameras to AI/robotics companies that need structured, embodied training footage (e.g., manipulation tasks, navigation workflows).

## Technical Architecture & Stack
The project is built using a modern Next.js ecosystem, prioritizing a decoupled API pattern for the core marketplace actions while leaning on background workers for media processing.

*   **Frontend & API**: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4.
*   **Database**: PostgreSQL hosted via Neon DB.
*   **ORM**: Prisma Client v6.4.1.
*   **Authentication**: `next-auth` (v5 Beta) utilizing a custom Credentials Provider and `bcryptjs` to manage secure logins.
*   **Background Jobs**: `bullmq` powered by a local Redis instance (`ioredis`) handles async video processing simulations.
*   **Payments (Mocked)**: Prepared structure for Stripe Connect payouts using `payment_ledger` tracking.
*   **Storage (Mocked)**: Outlined AWS S3 usage (`@aws-sdk/client-s3`) via placeholder Signed URLs.

## Key Design Decisions & Patterns

### 1. Database Schema (`prisma/schema.prisma`)
The domain model strictly maps to the required workflow:
*   **Users**: Unified table categorized via `Role` enum (`CREATOR`, `COMPANY`, `ADMIN`).
*   **Missions**: The core ontology entity that companies create containing task requirements, constraints, and pricing.
*   **Submissions**: Tied to a specific mission and creator. Tracks the `ProcessingStatus` state machine from `UPLOADED` -> `PROCESSING` -> `IN_REVIEW` -> `ACCEPTED`/`REJECTED`.
*   **Datasets & Samples**: When an admin accepts a submission, the system auto-generates or updates a Dataset object for that specific company/mission and creates a `DatasetSample` join record.
*   **PaymentLedger**: Tracks gross/net payout amounts and the platform fee (configured to 20%) in preparation for Stripe transfer webhooks.

### 2. Role-Based Access Control (RBAC)
*   **Middleware Level Protection**: NextAuth handles session JWT population. `src/middleware.ts` intercepts requests using `.startsWith` logic to enforce role segregation (e.g., blocking non-companies from `/api/v1/company` and non-creators from `/api/v1/creator`).
*   **Handler Level Protection**: Individual Next.js API route handlers (e.g., `src/app/api/v1/missions/route.ts`) explicitly double-check the `session.user.role` to prevent privilege escalation via direct API calls.
*   **Security Patch**: An early iteration allowed users to pass arbitrary roles during registration. This was explicitly patched to default all self-registered users safely to `CREATOR` (`role: "CREATOR" as Role`).

### 3. Background Processing Queue (`worker.ts`)
Because video processing (ffmpeg) and VLM (Vision-Language Model) labeling are slow, they are detached from the HTTP request cycle.
*   The API `complete-upload` endpoint pushes a job to BullMQ.
*   A separate Node.js process (`worker.ts`) connects to Redis, picks up the job, simulates the ffmpeg/VLM delay, populates the database with mocked metadata (resolution, duration, fps) and `labels_summary` (JSON), and transitions the status to `IN_REVIEW`.
*   *Optimization Note*: During Next.js static builds, eagerly connecting to Redis via `ioredis` causes aggregate errors due to the build sandbox lacking the service. The connection inside `src/lib/queue.ts` was refactored to be lazily instantiated via a JavaScript `Proxy` to safely bypass Next.js build-time errors.

### 4. UI Structure (`src/app`)
Rather than single generic dashboards, the UI is split cleanly by Role:
*   `app/creator/page.tsx`: Queries `OPEN` missions, provides an "Accept & Upload" action that successfully simulates fetching a presigned URL and advancing the submission state.
*   `app/company/page.tsx`: Manages forms for mission generation and fetches structured auto-generated datasets representing accepted deliverables.
*   `app/admin/page.tsx`: Fetches the `IN_REVIEW` queue and exposes dispatch buttons to trigger `ACCEPTED` or `REJECTED` workflows (which internally trigger the payout ledger and dataset inclusion logic).

## Known Limitations & Future Roadmap
*   **Real Media Storage**: Currently, the system uses mocked `https://mock-storage.com` strings. It needs to be wired up using real `AWS SDK` `getSignedUrl` commands pointing to an S3/Wasabi/R2 bucket.
*   **Real Video Processing**: `worker.ts` currently `setTimeout`s and inserts hardcoded JSON. This must be replaced with `fluent-ffmpeg` binaries and API calls to actual VLMs (e.g. Gemini/GPT4-Vision).
*   **Real Payments**: Payout ledgers simply `console.log` a "Mock Stripe Transfer". Implementation requires the `stripe.transfers.create` SDK logic alongside Creator onboarding workflows.
*   **Docker Environments**: Local execution utilizes a standard Node `npm run dev` and native `redis-server` due to restrictive Docker overlayfs container permissions on this specific host sandbox environment.

## File Organization Summary
*   `src/app/api/v1/`: Houses all decoupled REST API endpoints.
*   `src/app/`: Houses the Next.js React UI dashboards (`creator`, `company`, `admin`).
*   `src/lib/`: Reusable singletons (`prisma.ts`, `auth.ts`, `queue.ts`, `payments.ts`).
*   `prisma/seed.ts`: Seed script managing the initial state.
*   `worker.ts`: External headless background processor script.
*   Global Documentation: `README.md`, `VISION.md`, `ROADMAP.md`, `TODO.md`, `HANDOFF.md`, `AGENTS.md`, and `CHANGELOG.md` are accurately populated to ensure safe handoff to future LLM agents.

**Architecture Overview**
SkillzHub is a C2B marketplace MVP built to connect creators capturing specialized GoPro/FPV footage with companies training embodied AI models and robots. 
*   **Frontend/Backend Engine:** Next.js 16.2.6 (App Router) heavily utilizing Server Components, Server Actions, and Route Handlers for the API layer.

*   **Authentication:** NextAuth (v5 Beta) utilizing `bcryptjs` for local email/password authentication. The `middleware.ts` enforces Role-Based Access Control (RBAC) across Creator, Company, and Admin routes.
*   **API Security:** API Routes are protected via Zod validation schemas (`src/lib/schemas/index.ts`). Programmatic API key access uses SHA-256 hashing for fast O(1) lookups to prevent bcrypt-based DoS attacks. A simple token-bucket rate limiter (`src/lib/rate-limit.ts`) uses Redis and an atomic Lua script.
*   **Background Processing:** BullMQ running on top of an `ioredis` client handles async video processing tasks (normalization, metadata extraction, labeling) triggered on file upload. Lazy instantiation of Redis clients avoids Next.js static build errors.
*   **Styling & UI:** Tailwind CSS v4, Lucide React icons, and Recharts for dashboard analytics.

**Current State & Mocked Boundaries**
The core MVP loop is functional (Mission Creation -> Submission -> Auto-Processing -> Admin Review -> Dataset Generation -> API/Manifest Access). However, several critical systems rely on mocks designed for local execution and rapid iteration:
*   **Storage (`src/lib/storage.ts`):** `generatePresignedUploadUrl` and `generateDownloadUrl` return mock URLs (`https://mock-storage.com/...`). The real AWS S3/Cloudflare R2 integration is stubbed.
*   **Payments (`src/lib/payments.ts`):** `processPayouts`, `createConnectAccount`, and `createOnboardingLink` simulate Stripe Connect interactions. Real payout execution is skipped.
*   **Video Processing (`worker.ts`):** ffmpeg normalization, VLM-based auto-labeling (action summary, object tags, environment tags), and metadata extraction are simulated with fixed outputs (`duration_seconds: 120`, `resolution: "1080p"`).
*   **UI Views:** The Admin review queue uses HTML5 placeholder videos.

*   **Separation of Concerns:** DB logic lives in `lib/prisma.ts`, Auth logic in `lib/auth.ts`, validation in `lib/schemas/index.ts`, background processing in `worker.ts`, and core API definitions in `app/api/v1/`.
*   **Fail-Open Mechanics:** The rate limiter fails open (returns `true`) if Redis is unreachable, prioritizing availability over strict enforcement during outages.
*   **Idempotency & Upserts:** During Dataset generation in the Review API, the system checks if a Dataset exists for the specific Mission before creating a new one, mitigating duplicate datasets if multiple submissions are accepted simultaneously.

*   **Data Aggregation:** Dedicated analytics endpoints (`/api/v1/company/analytics`) leverage Prisma's `groupBy` and `aggregate` functions to generate complex charting data (Total Capital Deployed, Pipeline Status Distributions, Dataset Volumes) rendered via Recharts on the frontend.
*   **Error Boundaries:** The UI implements `src/app/error.tsx` and `src/app/global-error.tsx` to trap unhandled runtime errors, replacing raw server stack traces with graceful, user-friendly recovery prompts.
